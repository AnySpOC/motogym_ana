# 2026-11-07 走行データ解析

## 対象

- アプリCSV: `gym-ana-selected-2026-11-07T07-37-16-848Z.csv`
- GoPro GPX: `GX010088.gpx`
- GoPro映像: `GX010088.MP4`
- 解析日: 2026-11-07

位置情報と映像は解析入力にだけ使用し、リポジトリへ保存しない。速度とSTART/STOPの数値評価には、映像と同じGoProから得たGPXを独立参照として使用した。

## 結果概要

- GPS品質条件を通過して時刻同期できた走行は11走、5,873比較点だった。
- 内訳は自動計測9走、手動計測2走である。
- 現行EKFの時刻整列RMSEは2.840 km/h、走行ごとの平均RMSEは2.770 km/hだった。
- 最良係数候補のRMSEは2.839 km/hで、改善率は0.05%に留まった。
- 過去分を含む評価は7日、21走、17,295点で、現行RMSE 3.530 km/hに対して最良候補3.529 km/hだった。日別悪化もあるため速度係数は変更しない。

## STARTとSTOP

GoPro GPXと同期できた自動START 9件のうち、7件はSTART時0.05から2.37 km/hだった。次の2件はSTART時に約5.3 km/hへ達していた。

| UTC | GoPro速度 | 観測 |
|---|---:|---|
| 07:17:13.791 | 5.280 km/h | 弱い前後Gが続いた後に学習しきい値を超過 |
| 07:30:05.296 | 5.297 km/h | iPhone GPSもSTART直前に走行速度へ更新 |

両走行とも、速度推定器の遅れより前にSTARTイベント自体が遅れている。振動の大きさから学習された発進しきい値は約0.180 Gで、実発進中の前後Gは約0.13から0.17 Gの区間が長かった。単一しきい値を下げるだけではエンジン振動による誤STARTを増やすため、強発進と緩発進を別の継続条件にした。

同期できた自動STOP 9件のGoPro速度は0.37から1.48 km/hだった。単一点のGPS速度ではなく、複数観測、滞留距離、低運動の継続を使う現行STOP判定は維持する。

## v39改善

1. 強発進は従来どおり学習しきい値を100 ms継続して検出する。
2. 緩発進は`max(0.12 G, stationaryG + 0.04 G, startG * 0.72)`を350 ms継続して検出する。
3. どちらも候補先頭までSTART時刻を戻し、確認中の加速度を初期速度へ引き継ぐ。
4. 緩発進候補中にGPSが走行速度へ更新されても、候補を破棄しない。
5. 自動START時のiPhone GPS速度が2 km/hを超えた走行は`AUTO_START_GPS_MOVING`として品質確認対象にする。

## 判定と次回確認

今回のデータだけを理由にEKF、UKF、粒子フィルタへ変更する根拠はない。主な誤差はGPS基準の平滑化、時刻差、START遅延であり、より複雑な速度フィルタ候補は過去日へ一般化しなかった。

次回はv41を表示したiPhoneで、通常発進1回と意図的な緩発進2回を含む閉鎖コース3走を行う。3走を選択CSVで出力し、`npm run audit:field -- --csv <CSV>`でSTART/STOP、自動再待機、保存、検出方式、START時GPS速度、確定待ち時間、品質を一括判定する。
