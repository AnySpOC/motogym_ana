# 既存データ改善シミュレーション（2026-10-17）

## 1. 結論

既存のiPhone CSVとGoPro GPXだけでも、速度モデルの係数候補をログ再生で比較できる。今回、`C:\Users\foxho\Videos`以下のCSV 10本とGPX 9本をUTC時刻で自動照合した。途中にセンサー欠測がある走行は2秒以内で連続する区間へ分割し、品質条件を満たした4日分8区間を用いて、通常モデル400通りと実時間モデル200通りを評価した。

再生器はv23と同じ速度・前後Gの2状態EKFを再現する。全データに最適化した候補は現行より改善したが、総合RMSEの改善は`3.959 km/h`から`3.930 km/h`（約0.7%）に留まった。また、日付単位の交差検証では4日すべてで現行設定よりわずかに悪化した。したがって、今回はアプリの速度係数を変更しない。

この結果は「改善できない」という意味ではない。既存データで候補を安全に棄却できる評価基盤ができ、現行設定が複数日に対して頑健であること、人工抵抗を加える候補は過学習の疑いがあることを確認できた。

## 2. 評価方法

1. CSVファイル名のUTC開始時刻と`time_ms`からiPhone各サンプルの絶対時刻を復元した。
2. GPXの2021年・座標`0,0`などの異常点を除外し、前後約1秒の移動距離から基準速度を算出した。
3. CSVとGPXを時間重複で自動対応付けした。
4. iPhone GPS対GPXの時間差を走行ごとに一度だけ推定し、全候補で同じ時間差を使用した。
5. v23の速度・前後Gの状態と共分散更新を再現し、人工抵抗、プロセスノイズ、GPS観測誤差倍率、GPS遅延予測の400通りを探索した。
6. ある日を評価用に隠し、残りの日だけで係数を選ぶ日付単位の交差検証を行った。
7. UTCをずらさない実時間評価で、GPS更新間の加速度補間、加速度倍率、バイアス学習、0から2秒の遅延補償を200通り探索した。

品質条件は、連続区間10秒以上、GPX重複10秒以上、iPhone GPS相関0.7以上、GPS RMSE 8 km/h以下である。候補の順位は走行ごとのRMSE平均に絶対バイアスの15%を加えて決めた。

### 実時間・遅延補償評価

波形の最良時刻合わせとは別に、UTCをずらさない評価を行った。現行は`5.205 km/h`、最良候補は`5.168 km/h`だった。最良候補はGPSを毎回100%採用し、加速度を0.8倍、0.5秒分だけ進め、弱いバイアス学習を行う方式だが、交差検証では10月4日、10日、12日に悪化した。表示遅延対策としても採用しない。

評価器は、総合RMSEが10%以上改善し、かつ未知日のすべてで現行以下になった場合だけ`accepted: true`を出力する。今回の通常評価と実時間評価はいずれも`false`である。

## 6. 実行方法

```powershell
cd C:\app\gym_ana\repo
npm run evaluate:existing -- --root C:\Users\foxho\Videos
```

JSONを保存する場合は次を使用する。

```powershell
npm run evaluate:existing -- --root C:\Users\foxho\Videos --json docs\generated\existing-data-replay.json
```

新しいCSV/GPXを同じルート以下へ追加すれば、スクリプトが再帰的に検出する。GoPro MP4を毎回解析する必要はなく、速度係数の一次評価は短時間で再実行できる。

## 7. 次の判断

現時点では係数変更よりも、v23で正常に停止状態から始めた自動計測を3本以上追加する方が価値が高い。次回ログではSTART前5秒からIMU/GPSを保存する形式へ変更すると、過去ログ再生でSTART閾値と保持時間まで探索できる。新データ追加後に同じ交差検証で総合RMSE 10%以上の改善があり、すべての評価日で現行以下になった場合に係数変更を採用する。
