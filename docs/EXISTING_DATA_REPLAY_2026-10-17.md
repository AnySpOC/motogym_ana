# 既存データ改善シミュレーション（2026-10-17）

## 1. 結論

既存のiPhone CSVとGoPro GPXだけでも、速度モデルの係数候補をログ再生で比較できる。今回、`C:\Users\foxho\Videos`以下のCSV 10本とGPX 9本をUTC時刻で自動照合し、品質条件を満たした4日分4走行を用いて400通りを評価した。

全データに最適化した候補は現行より改善したが、総合RMSEの改善は`4.119 km/h`から`4.068 km/h`（約1.2%）に留まった。また、日付単位の交差検証では10月10日の未知データに対して現行設定より悪化した。したがって、今回はアプリの速度係数を変更しない。

この結果は「改善できない」という意味ではない。既存データで候補を安全に絞れる評価基盤ができ、現行設定が少なくとも極端に悪くないこと、人工抵抗を加える候補は過学習の疑いがあることを確認できた。

## 2. 評価方法

1. CSVファイル名のUTC開始時刻と`time_ms`からiPhone各サンプルの絶対時刻を復元した。
2. GPXの2021年・座標`0,0`などの異常点を除外し、前後約1秒の移動距離から基準速度を算出した。
3. CSVとGPXを時間重複で自動対応付けした。
4. iPhone GPS対GPXの時間差を走行ごとに一度だけ推定し、全候補で同じ時間差を使用した。
5. 現在の速度再生モデルについて、人工抵抗、プロセスノイズ、GPS観測誤差倍率、GPS遅延予測の400通りを探索した。
6. ある日を評価用に隠し、残りの日だけで係数を選ぶ日付単位の交差検証を行った。

品質条件は、GPX重複10秒以上、iPhone GPS相関0.7以上、GPS RMSE 8 km/h以下、サンプル欠落2秒以下である。候補の順位は走行ごとのRMSE平均に絶対バイアスの15%を加えて決めた。

## 5. 発進・停止の監査

旧CSVはSTARTした時点からしかiPhone IMUを保存していない。このため、現在のv23発進判定を過去データだけで正確に再生することはできない。GPX速度によるイベント時刻の監査は可能である。

|10月4日|算出不可|自動停止|0.304 km/h|自動停止は妥当|

|10月12日|13.175 km/h|画面切替中断|21.903 km/h|計測走行ではない|

10月4日の自動STOPは正しく、過去の誤STARTも数値で再確認できた。ただしv23で追加した車種別キャリブレーションと静止確認の改善効果は、新しい発進前ログがなければ検証できない。

## 6. 実行方法

```powershell
cd C:\app\gym_ana\repo
npm run evaluate:existing -- --root C:\Users\foxho\Videos
```

JSONを保存する場合は次を使用する。

```powershell
npm run evaluate:existing -- --root C:\Users\foxho\Videos --json docs\generated\existing-data-replay.json
```

新しいCSV/GPXを同じルート以下へ追加すれば、スクリプトが再帰的に検出する。GoPro MP4を毎回解析する必要はなく、速度係数の一次評価は短時間で再実行できる。

## 7. 次の判断

現時点では係数変更よりも、v23で正常に停止状態から始めた自動計測を3本以上追加する方が価値が高い。次回ログではSTART前5秒からIMU/GPSを保存する形式へ変更すると、過去ログ再生でSTART閾値と保持時間まで探索できる。新データ追加後に同じ交差検証で総合RMSE 10%以上の改善があり、すべての評価日で現行以下になった場合に係数変更を採用する。
